# Product

## Who it is for

OEM software engineers (about 1–5 years of experience, solid Linux and C++/Java) who customize AOSP/AAOS for in-vehicle infotainment at the system level and were never systematically taught how.

## What success looks like

A reader finishes a lecture in an evening, completes its lab on an emulator or Cuttlefish without real car hardware, and can do the corresponding OEM task at work the next week: build a product, add a service, wire a vehicle property, fix a boot failure, ship an OTA, face a VTS run.

## Confirmed direction (grill rounds 1–4, 2026-11-08)

- Public, English-only, CC BY-NC-SA. Upstream AOSP/AAOS only, pinned to Android 17 / AAOS 26Q2.
- Jekyll on GitHub Pages. The site should read like MIT's Missing Semester: syllabus homepage, plain academic layout, fast, no marketing.
- 12 lectures in OEM lifecycle order, each with the same shape, plus a capstone, a kernel pointer path, an app pointer path, setup, and glossary.
- Mode for every surface: Read. Precision and restraint beat expression.

## Non-goals

Video, translations, quizzes, app UI development, kernel internals, proprietary BSP content.
